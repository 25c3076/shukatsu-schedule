# Gmail連携 仕様書

最終更新: 2026-10-20
状態: **確定**

---

## 1. 目的

企業からの新着メールをアプリ内で知らせ、**重要な連絡や提出期限の見落としを防ぐ**。

- メールの内容はGmailで本人が読む(アプリは「届いたこと」を知らせる役)
- 必要な締切は、本人がタスクとして手動で登録する

---

## 2. 前提・構成

| 項目 | 内容 | 理由 |
|---|---|---|
| 起動方法 | `起動.command` → `http://localhost:5500` | Googleのログインは `file://` では動かないため |
| サーバー | 使わない(ブラウザだけで完結) | 構成をシンプルに保つため |
| ログイン方式 | Google Identity Services(トークン方式) | ブラウザだけで使えるGoogle公式の方式 |
| 権限 | `gmail.readonly`(読み取り専用) | Gmailの検索で、必要なメールだけに絞り込めるため |
| アプリの公開状態 | テスト(テストユーザー=自分のみ) | Googleの審査が不要なため |
| クライアントID | 設定画面に貼り付けて保存 | ファイルを書き換えずに設定できるようにするため。秘密情報ではない |
| クライアントシークレット | **使わない・保存しない** | ブラウザだけの方式では不要。漏れると危険なため |
| アクセストークン | **メモリ上だけに保持**(保存しない) | 有効期限は約1時間。保存すると漏えいのリスクがあるため |

### 制約(仕組み上避けられないこと)
- アクセストークンは約1時間で切れる。**再取得には「再接続」ボタンのクリックが必要**(ブラウザは、クリックなしでGoogleのログイン画面を開くことを許さないため)。
  → 切れている間は自動確認が止まり、「再接続してください」と表示する。
- 同じ理由で、**アプリを開いたときも「接続」ボタンのクリックが1回必要**(トークンを保存しない方針のため)。
  → 接続済みの設定があれば、開いたときに「接続して新着を確認」ボタンを表示し、押すとすぐに確認する。
- アプリを閉じている間は確認できない。

## 3. 機能一覧

### 3-1. 接続・切断(設定画面)
| 機能 | 理由 |
|---|---|
| クライアントIDの入力欄 | Googleに接続するために必要 |
| 「Gmailに接続」「再接続」「切断」ボタン | 接続状態を本人が管理できるように |
| 接続中のアカウント、最終確認日時の表示 | 正しいアカウントで動いているか確認できるように |

### 3-2. 新着メールの確認(A・C)
- 確認するタイミング
  - アプリを開いたとき(「接続」ボタンを1回押す。上記の制約を参照)
  - 「更新」ボタンを押したとき
  - 開いている間は **5分おき** に自動確認
- 初回は過去 **14日分** をさかのぼって取得
- 2回目以降は、前回確認した時刻以降のメールを取得(取りこぼし防止のため1日分重ねて検索し、取得済みのメールは除く)
- 企業の追加や送信元の変更で照合の条件が変わったときは、もう一度過去14日分を検索する(後から登録した企業のメールも拾うため)
- 設定画面の「過去のメールを読み込み直す」で、過去14/30/60/90日分を手動で検索し直せる(取得済みのメールは除く)

### 3-3. 企業からのメールの見分け方(B)
次のどちらかに一致したメールを、その企業のメールとする。
1. **送信元ドメイン**が、企業情報の「メールの送信元」に一致(サブドメインも含む。例: `mail.example.co.jp` は `example.co.jp` に一致)
2. **件名**に企業名が含まれる(就活サイトや採用管理システムなど、共通のドメインから届くメールを拾うため)

- どちらにも一致しないメールは**取得・表示しない**
- 1通が複数の企業に一致した場合 → **ユーザーが手動で企業を選ぶ**(選ぶまでは「企業未選択」としてメール一覧で目立たせる)

### 3-4. 表示する場所(D)
| 場所 | 内容 | 理由 |
|---|---|---|
| メール画面 | 一致したメールの一覧。未確認の件数をバッジ表示 | 見落とし防止の中心 |
| ダッシュボード | 「未確認のメール N件」のカード | 起動時にすぐ気づけるように |
| 企業詳細 | その企業から届いたメールの一覧 | 企業ごとの経緯をまとめて追えるように |
| 企業一覧 | 未確認メールがある企業の行に通知アイコン | どの企業から連絡が来ているか一目でわかるように |

**レイアウト(決定)**
- メール一覧: 届いた順に1行1通。企業未選択のメールは黄色で一番上に表示し、その場で企業を選ぶ
- ダッシュボード: 数字のカード「未確認のメール N件」を1枚追加(押すとメールの画面へ)
- 企業一覧: 未確認メールがある企業の名前の横に「✉ N」
- 企業詳細: 左側「タスク・提出物」の下に「メール」カード(新しい5件まで)
- メール・カレンダーの入口: タブにはせず、**メイン画面の右上にアイコンだけで置く**(マウスを乗せると名前を表示)。メールのアイコンに未確認件数のバッジ(青)
- サイドバーのタブは「ダッシュボード・企業・タスク・締切」の3つ

### 3-5. 確認済みの管理(E)
- Gmailの既読・未読とは別に、アプリ内だけの「確認済み」チェックを持つ
- 「締切をタスクに登録した」または「対応不要と判断した」ときに、本人が確認済みにする
- 理由: Gmailで開いて既読にしただけで、締切の登録を忘れるのを防ぐため

### 3-6. メールからの操作(F)
| 操作 | 内容 | 理由 |
|---|---|---|
| Gmailで開く | メール一覧で**件名をクリック**すると、新しいタブでGmailの該当メールを開く | 内容はGmailで読むため。ボタンを減らして一覧を見やすくするため |
| タスクとして登録 | 件名と企業が入った状態でタスクのフォームを開く。締切日は本人が入力 | 締切の登録の手間を減らすため |
| タスクと元メールのリンク | 登録したタスクから元のメールへ、メールから登録したタスクへたどれる | 「この締切はどのメールの話か」を後から確認できるように |

- 見せ方(決定):
  - タスク一覧の行に「✉ 元のメール」(押すとGmailで元メールを開く)
  - メール一覧の行に「☑ タスク登録済み:(タスク名)」(押すとタスクの詳細)
  - タスクの編集画面に「元のメール」欄
- メールからタスクを登録したら、そのメールを**自動で確認済み**にする(手動で戻せる)
- 締切日の自動読み取りは**しない**(誤った日付で登録される危険があるため)

## 4. 保存するデータ(G)

localStorage と JSONバックアップに、次の項目**だけ**を保存する。本文や冒頭の一部(スニペット)は保存しない。

```js
mails: [{
  id,          // GmailのメールID(重複取得の防止・「Gmailで開く」に使う)
  from,        // 送信元(表示名とアドレス)
  subject,     // 件名
  date,        // 受信日時
  companyId,   // どの企業のメールか(複数一致で未選択の間は空)
  candidateIds,// 複数の企業に一致したときの候補(選択用)
  checked      // アプリ内の確認済みフラグ
}]

tasks: [{ ..., mailId }]   // メールから登録したタスクに、元メールのIDを持たせる(F)

settings.gmail: {
  clientId,        // クライアントID
  account,         // 接続したGmailアドレス(表示と「Gmailで開く」のアカウント指定に使う)
  lastCheckedAt,   // 最終確認日時
  pollMinutes: 5   // 自動確認の間隔
}
```

- メールの記録は無期限に残す。企業を削除したら、その企業のメール記録も削除する

## 5. 作らないもの

| 機能 | 作らない理由 |
|---|---|
| メールの送信 | 目的(見落とし防止)に不要 |
| Gmail側の操作(既読にする、ラベル付けなど) | 読み取り専用の権限で十分。誤操作を防ぐため |
| アプリを閉じているときの通知 | サーバーが必要になり、構成が大きく変わるため |
| 締切日の自動読み取り | 誤った日付で登録される危険があるため |
| 一致しないメールの「未分類」表示 | 判定が難しく、関係ないメールが大量に混ざるため |
