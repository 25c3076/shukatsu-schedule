# データ同期(Firebase)仕様書

最終更新: 2026-10-27
状態: **確定**

---

## 1. 目的

外出先やスマホからでも、PCと**同じデータを見て、編集できる**ようにする。

---

## 2. 構成

| 項目 | 内容 | 理由 |
|---|---|---|
| アプリの置き場所 | GitHub Pages(コードは公開、データは含めない) | 無料で、どこからでも開けるため |
| データの保存先 | Firebase の Firestore(東京リージョン) | 端末をまたいで同じデータを使うため |
| ログイン | Firebase Authentication(Googleアカウント) | 一度ログインすれば、ログイン状態が続くため |
| ログインできる人 | Google Cloud の「テストユーザー」に登録したアカウントのみ | 他人が使えないようにするため |
| データの保護 | Firestore のルールで「本人のデータは本人だけが読み書きできる」 | firebaseConfig は公開されるため、ルールで守る |
| Firebase の SDK | 公式CDN(gstatic)の compat 版を `<script>` で読み込む | ES Modules を使わない今の作りのまま使えるため |

### データの置き場所
- Firestore: `users/{ログインしたユーザーのID}/data/main`
- 中身: アプリの全データを JSON 文字列として1つにまとめて保存(`json`)、更新日時(`updatedAt`)、更新した端末(`device`)
- 1つの文書の上限は約1MB。就活1シーズン分のデータ(企業数十社、メール数千通)なら収まる

## 3. 動き

### 3-1. ログイン
- ログインしていないときは、ログイン画面だけを表示する(**ログイン必須**)
- 「Googleでログイン」ボタン → Googleの画面でアカウントを選ぶ
- `file://`(index.html を直接開く)では Firebase のログインが動かないため、案内を表示して使えないようにする
  → PCでは `起動.command`(localhost)か、公開したURLから開く

### 3-2. 初めてログインしたとき(その端末で初めて)
| この端末のデータ | クラウドのデータ | 動き |
|---|---|---|
| なし | なし | ようこそ画面(サンプルで試す / 空で始める / JSONから復元) |
| あり | なし | この端末のデータをクラウドに送る |
| なし | あり | クラウドのデータを使う |
| あり | あり | **どちらを使うか、件数を見せて選ばせる**(選ばなかった方は上書きされる) |

### 3-3. 保存と反映
- 編集するたびに、まず**この端末(localStorage)に保存**し、約1秒後に**クラウドへ送る**
- 送る前にこの端末へ「未送信あり」の印を付け、送れたら消す。電波がなくて送れなかった分は、次につながったときに送る
- 別の端末で編集された内容は、**自動で画面に反映**する(入力中・ポップアップ表示中は、閉じてから画面を描き直す)
- 2台で同時に編集した場合は、**後から送った内容で上書き**される(1人で使う前提のため)

### 3-4. ログアウト
- 設定画面の「ログアウト」から行う
- **この端末のデータは削除する**(クラウドには残る)。他人の端末でログインした場合にデータを残さないため
- 未送信の変更がある場合は、送ってからログアウトする(送れなければ確認を出す)

### 3-5. すべてのデータを削除
- **この端末とクラウドの両方から削除**する(2回確認)
- ほかの端末で開いている画面にも、削除が反映される

### 3-6. そのほか
- JSONバックアップ(保存・読み込み)はそのまま使える。読み込んだ内容はクラウドにも送る
- Gmail連携の設定(クライアントIDなど)は同期される。Gmailへの接続は端末ごとに必要
- 画面左下に同期の状態を表示する(同期済み / 送信中 / オフライン / エラー)

---

## 4. 作らないもの

| 機能 | 作らない理由 |
|---|---|
| ログインしないで使うモード | 端末ごとにデータが分かれる状態に戻ってしまうため |
| 項目ごとの細かい同時編集の統合 | 1人で使う前提では、上書き方式で十分なため |
| 他人とのデータ共有 | 目的外のため |
